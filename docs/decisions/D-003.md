## 争点

包形态、公开面与版本承诺：拆单元还是保持单文件；是否做包根迁移。

## 判据（逐条）

| # | 判据 | 来源 |
| --- | --- | --- |
| 1 | 消费方可 `import`，不需复制单文件 | R-E-01 |
| 2 | 公开面最小、可枚举、实现细节不进生成头 | R-E-02 |
| 3 | 编译器下限与依赖有声明 | R-E-04 |

## 判决（upheld）

1. 口径 A：单包多单元（当前 `src/json.h.ct`），不恢复单文件复制形态。
2. PH-6 产出冻结的导出清单与脚本比对（`pub` 符号清单 + 生成头不含 `main`/demo/测试）。
3. 保持 `requires = ct >= 0.53.0`；PH-6 补 `//@ct-requires` 与清单一致。
4. 包根迁移（backlog #10）暂不做：当前 `namespace = json` + `import json::src::json;` 可消费，迁移留待共享库/包根约定落地。
5. 版本承诺 0.x；不承诺 C ABI。

## 生效范围

PH-6 的 R-E-02/R-E-04 任务；README「As a package」与 `ct.pkg` 注释。

## 理由

包已能装能 import（JSON-4），拆单元已完成；剩余价值在「公开面冻结 + 依赖声明」，不在再搬目录。包根迁移会改所有消费方路径，收益不足且与共享库机制冲突。

## 失效条件

共享库/包根约定在本仓落地，或消费方要求 `import json::json;` 时重开。

## 影响面

PH-6；ACC-33/34/36；`docs/spec/ct-json-delivery-backlog.md` 第 1、3、4 项。
