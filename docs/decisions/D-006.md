## 争点

编码失败的契约、实数输出格式，以及旧 `JsonOut` 追写器是否仍在承诺范围内。

## 判据（逐条）

| # | 判据 | 来源 |
| --- | --- | --- |
| 1 | 非有限实数不得写出 `nan`/`inf` | R-B-03 |
| 2 | 输出能被本包重新解析且值等价 | R-B-07 |
| 3 | 公开面只承诺存在的 API | R-B-01、R-B-05 |

## 判决（upheld）

1. `json_encode` 分配并返回缓冲，没有调用方缓冲；R-B-05 的「截断可判定」**不做**，不新增 `JSON_EMIT_TRUNCATED`。
2. 旧 `JsonOut` 追写器不在包公开面（只在已废止的 `json.ct` 里）；R-B-01 的「状态机错误」**不做**。
3. 实数输出保持当前的**最短往返**（`%.*g` 从 1 位试到 17 位），不用 `%.17g`。
4. 非有限实数必须拒绝：`json_encode` 返回 `NULL` + `JSON_ERR_RANGE`。当前 `{"x":nan}` 是缺陷，PH-5 修（`JSON-9`）。

## 生效范围

PH-5 的 R-B-03 修复与 R-B-07 往返用例；README 与 spec 删除旧 `JsonOut` 承诺（PH-6 文档收口）。

## 理由

保留不存在的 API 契约会让验收无法执行；最短往返已经实现且优于 `%.17g`。非有限值必须拒绝是「输出合法 JSON」的底线，不能降级。

## 失效条件

恢复调用方缓冲 API（例如 `json_encode_into`）时重开截断契约；或出现最短往返不可接受的消费方时重开数字格式。
