# ADR-0003：写入采用引用共享与引用计数

- 状态：已采纳（Accepted）
- 日期：2026-11-15
- 裁定者：用户（第 8 条，选项 C）
- 回答：ADR-0002 待定 1（拷贝值还是接管所有权）与待定 2（删除后外部引用）
- 后续回答：环的处置见 [ADR-0005](0005-cycle-handling.md)；计数 API 公开见 [ADR-0006](0006-public-refcount.md)
- 前提：[ADR-0001](0001-tree-data-model.md) 树模型、[ADR-0002](0002-mutable-scope.md) 读 + 写范围
- 影响面：公开所有权语义。本 ADR 不含实现，不改变当前 `json.ct`。

## 决策

把值写入容器时**不拷贝、不转移所有权**：写入的是同一个对象的引用。生命周期由引用计数管理——容器持有算一个引用，外部持有算一个引用，计数归零才释放。

## 理由

与 JavaScript 行为一致：`b = a; b.x = 1;` 之后 `a.x` 也能看到 1，因为 `a` 与 `b` 指向同一个对象。若选拷贝，写入后两边是两份，改哪边另一边都看不见；若选转移，写入后调用方手里的引用失效，也不能再用。两条都会让「JS 风格」打折。

## 与 ADR-0001 的关系

结构上仍按树构造（对象、数组、标量，对象保插入序），但允许多个父持有同一个子对象，形式上是 **DAG**，不是严格树。0001 的「树」指构造方式与公开模型，不限制共享；该处措辞已加注，两份 ADR 不冲突。

## 待定 2 如何被回答

删除键或删除数组元素，只是解除容器对子对象的一个引用，计数减一。外部若还持有引用（计数 > 0），对象继续存活，指针仍有效；计数归零才释放。因此**不需要版本号或失效判定**——引用计数本身就是存活判定。

## 后果

### 1. `json_free` 从「无条件销毁」变为「减计数」

调用 `json_free` 是**放弃自己这一份引用**，不是无条件销毁对象：

- 调用之后，该引用对调用方即失效，不得再用；
- 只要还有别的持有者，对象不会立刻释放；计数归零时才真正释放；
- 未调用 `json_free` 之前，该引用保证对象存活；
- 容器删除键/元素只减容器那一个计数，不影响外部持有的引用。

### 2. 同一对象挂两处，encode 输出两份

`v["a"] = child; v["b"] = child;` 编码结果是两份 `child` 的副本。这与 `JSON.stringify` 的行为一致，**不是缺陷**，文档要明说，避免调用方以为是去重或引用标记。

### 3. 共享允许写出环

> **已由 [ADR-0005](0005-cycle-handling.md) 回答（2026-11-15）：** 写入不检测，encode 期用祖先栈或深度上限挡住并返回错误；成环视为调用方 bug，引用计数下会漏内存。

JSON 文本本身不会产生环，但 API 允许 `v["self"] = v` 这类写法。环的处理**待定**（见下；现已由 ADR-0005 回答），在裁定前不得声称「树永远无环」或「encode 一定能终止」。

### 4. 计数加减是否公开待定

> **已由 [ADR-0006](0006-public-refcount.md) 回答（2026-11-15）：** `json_retain` / `json_release` 全部公开，`json_free` 等于 release 一次；调用方须自行配对。

`json_retain` 之类的加计数入口是否作为公开 API，**待定**（见下；现已由 ADR-0006 回答）。在裁定前，公开面只承诺「写入共享 + `json_free` 减计数」，不承诺调用方能自行延长生命周期。

## 待定（留给用户裁定，本 ADR 不选；两条均已回答）

### 1. 环的处置

> **已由 [ADR-0005](0005-cycle-handling.md) 回答（2026-11-15）：** 写入不检测，encode 期挡住；以下原文保留备查。

- **写入时检测并拒绝**：写入前检查新子对象是否为自己或自己的祖先，命中即报错。后果：树/图永远无环，encode 可以无防护递归；代价是每次写入多一次祖先链检查（或维护标记），并要定义「拒绝」时的错误返回与树状态。
- **不检测，encode 做环路防护**：写入路径保持最简；后果是 encode 必须维护 visited 集合，且要定义遇到重复节点时的输出语义（报错 / 跳过并标注 / 直接展开），否则会无限递归或爆栈。

### 2. 引用计数加减是否公开

> **已由 [ADR-0006](0006-public-refcount.md) 回答（2026-11-15）：** 全部公开（`json_retain` / `json_release`）；以下原文保留备查。

- **公开**（`json_retain` / `json_release` 之类）：调用方可以单独持有树外引用、跨容器共享，生命周期能力完整。后果：API 面扩大，漏减计数会泄漏、多减会提前释放，误用成本高，且要与 `json_free` 的语义划清。
- **不公开**：计数只由容器与 `json_free` 内部维护，调用方无法单独延长生命周期。后果：公开面更窄、更难误用；代价是调用方想把一个子对象拿到树外长期保存时没有合法手段。

## 不做什么

- 不写实现、不恢复开发、不新建夹具、不修改 `json.ct`。
- 上面两条待定已分别由 [ADR-0005](0005-cycle-handling.md) / [ADR-0006](0006-public-refcount.md) 回答，本 ADR 不改写它们的原文。
