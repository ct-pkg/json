# ADR-0005：环在写入侧不检测，在编码期拒绝

- 状态：已采纳（Accepted）
- 日期：2026-11-15
- 裁定者：用户
- 回答：ADR-0003 待定 1（环的处置）
- 前提：[ADR-0003](0003-reference-sharing.md) 引用共享与引用计数
- 影响面：写入路径与编码错误契约。本 ADR 不含实现，不改变当前 `json.ct`。

## 决策

1. **写入不检测环**：`a["self"] = a`、互相引用都可以写进去。
2. **`encode` 必须挡住环**：用访问栈或深度上限，遇到环返回错误，**不许死循环、不许爆栈**。
3. 语义对齐 JavaScript：`JSON.stringify` 遇到循环结构抛 `Converting circular structure to JSON`；C 侧对应「编码失败并给出错误」，具体错误码不在本 ADR 决定。
4. **成环视为调用方 bug**：引用计数下成环的结构会漏内存，这是代价，不做环收集。
5. 可选提供显式的 `json_validate` 检查环；它**不在写入路径上**，不改变写入性能。

## 后果

- **编码防护必须按当前路径判断**：ADR-0003 已定同一对象挂两处时 encode 输出两份（DAG 合法）。所以防护不能用一个全局 visited 集合——那会把共享节点误判成环；要用祖先栈（当前递归路径）判断，或直接靠深度上限。
- **两种防护的副作用不同**：祖先栈只拒绝真正的环；深度上限同时会拒绝很深的无环结构。裁定允许二者之一，取舍由实现决定，但必须在文档里写明选了哪一种以及对应的深度值。
- **成环会漏内存**：计数不会归零，对象不释放；没有环收集器，`json_free` 也救不回来。文档要写明「成环是调用方 bug」。
- **编码错误时树不变**：只是写不出去，内存结构仍可继续使用；调用方可以改掉环再编码。
- **`json_validate` 是可选能力**：提供与否不影响上面的编码防护；不提供也不等于允许死循环。

## 未定（本次裁定未覆盖）

- 编码遇到环时返回哪个错误码、是否复用现有错误类型；
- 深度上限的具体数值，以及它与 ADR-0001「指针稳定」之外的结构限制如何共存；
- `json_validate` 的返回形式（布尔、错误码还是错误链）。

这些不在本 ADR 的裁定范围内，实现前需要另行拍板；本 ADR 不替用户选择。

## 不做什么

- 不写实现、不恢复开发、不新建夹具、不修改 `json.ct`。
- 不定义函数签名与错误码。
