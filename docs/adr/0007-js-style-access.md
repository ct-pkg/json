# ADR-0007：JS 风格访问是长期目标，当前 OO 调用是过渡

- 状态：已采纳（Accepted）
- 日期：2026-11-15
- 裁定者：用户
- 前提：[ADR-0001](0001-tree-data-model.md) 树模型、[ADR-0002](0002-mutable-scope.md) 读 + 写范围
- 影响面：公开 API 的**入口形状**（方法名、接收者、参数个数），不涉及签名细节与错误码
- 说明：ADR-0002 明确「不定义函数名与签名」；本 ADR 只补「入口形状」这一层约束，不替它定义完整签名

## 决策

1. **长期目标是与 JavaScript 一样的访问方式**：`data.server.port`、`data["server"]`、`items[0].name`。
2. **当前用面向对象的接口调用（`v.get("server")`）实现，只是过渡形态**。等 CT 补上下标语法糖之后，要完整实现下标调用。
3. 过渡形态**不能偏离**最终方向：现在定下的入口形状必须能被下标协议直接挂上，不能设计成以后再改一次。

## 对公开面的硬约束

### 1. 访问入口必须是方法，不是自由函数

- 必须有以**值为接收者**的方法入口：`v.get(k)`。
- 自由函数（`json_member(v, k)` 之类）可以留作内部实现或补充，**不能是唯一入口**。
- 这条约束的是「调用形状」，不限定用 trait 还是别的机制；接收者必须是值本身。

### 2. `get` 必须单参数、方法名为 `get`

- 单参数：`v.get(k)` / `v.get(i)`，下标协议只提供一个参数。
- 方法名必须是 `get`；不要为了当下方便改成 `get_member` / `get_value` 之类的分名。
- 不要为了「省一次调用」把参数变成多参；多参形状挂不上下标。

### 3. 数组访问给 `v[0]` 留位置

- 当前若用 `at` / `get_idx` 之类的分名，必须写明**这是过渡**。
- 最终由**参数类型匹配**统一到 `get`：键是字符串、下标是整数，同一个方法名，靠参数类型区分。
- 该统一依赖 CT 的参数类型匹配能力；在该能力落地前，分名只能是过渡，不得写成永久设计。

### 4. 写入面同理

- 写入必须是节点上的方法：`v.set(k, x)` / `v.set(i, x)`，键或下标在前、值在后。
- 同样不能只提供自由函数；同样不要用 `set_member` / `set_index` 作为永久分名。
- 追加式 `JsonOut` 可以保留为编码器，但它不是可写树的写入入口。

## 现有公开面的违背点

检查对象：当前实现 `json.ct` 的公开 trait（`json.ct:76-89`、`:105-123`、`:884-896`）与 README 的用法示例（`README.md:46-65`、`:185-192`）。

| # | 违背点 | 证据 | 改法 |
| --- | --- | --- | --- |
| V-1 | 访问入口的接收者是 `JsonDoc`，值只是参数；没有 `v.get(k)` 这种以值为接收者的入口 | `json.ct:114` `struct JsonView member(struct JsonView *v, const char *key);`；README 用法 `v = doc.member(&root, "name");`（`README.md:61`） | 最终树 API 把 `get` 定义在以值为接收者的方法上；自由函数保留为内部实现 |
| V-2 | 方法名不是 `get`：读用 `member` / `at`，类型读取用 `as_*` | `json.ct:114-115` | 访问统一到 `get`；`as_*` 属于取值转换，不属于下标入口，可保留但要与 `get` 分离 |
| V-3 | 访问是**多参**形状：`member(v, key)`、`at(v, index)`，下标协议只能传一个参数 | `json.ct:114-115`；`JsonValue` 的 `at(doc, v, index)`（`json.ct:887`）是三参 | 最终 `get` 单参（接收者之外只一个键或下标） |
| V-4 | 数组访问用分名 `at`，与键访问 `member` 分开 | `json.ct:115`、`:887` | 写明 `at` 是过渡名；最终由参数类型匹配统一到 `get` |
| V-5 | 写入面没有节点上的 `set`；只有追加式 `JsonOut`（`out.key` / `out.string` / `out.integer` …） | `json.ct:76-89`、README `README.md:84-95` | 最终写入 API 提供以节点为接收者的 `set`；`JsonOut` 只作编码器 |
| V-6 | 「只能通过自由函数访问」 | 未发现：当前访问都有方法形态（问题在接收者与参数，不在自由函数） | 无需改；保持「自由函数不得成为唯一入口」即可 |

**关于「当前 OO 形态能否直接挂下标」**：不能。接收者是 `JsonDoc` 而不是值，且键/下标与视图是两个参数；下标协议要求「值作为接收者、只带一个下标参数」。所以这不是「只差一个语法糖」，而是入口形状需要按上表调整。

## 依赖与风险

- `v[0]` 依赖 CT 的下标协议（L1）。该能力当前**未立项**（`ct-lang/docs/custom-index-protocol.md:3-11` 记「提案 / 未立项 / 未过分析，不作数」；`requirements-pool.md:9-20` 的 `REQ-L1` 仍为 `open`）。本 ADR 只定方向，不承诺时间点。
- 键与下标统一到 `get` 依赖参数类型匹配；该能力是否可用未在本 ADR 验证，落地前不得把「同名 `get`」写进已实现清单。
- 现有视图 API 已由 ADR-0001 废止，因此 V-1～V-5 **不在当前代码上直接改**；它们约束的是即将设计的树 API。记录在此，避免下一版 API 再犯。

## 不做什么

- 不写实现、不恢复开发、不新建夹具、不修改 `json.ct`。
- 不定义完整签名、返回类型与错误码。
- 不承诺 L1 下标或参数类型匹配的落地时间。
