# ADR-0002：公开范围包含写入与修改

- 状态：已采纳（Accepted）
- 日期：2026-11-15
- 裁定者：用户
- 废止对象：`DECISIONS.md` §6「不提供可变 API」
- 前提：`DECISIONS.md` §1 已被 [ADR-0001](0001-tree-data-model.md) 废止，树是唯一公开数据模型
- 影响面：公开能力范围。本 ADR 不含实现，不改变当前 `json.ct`。

## 决策

ct-json 的公开范围**包含写入与修改**，不只是只读遍历。

## 理由

目标是对齐 JavaScript 的 JSON 使用方式。在那种用法里，`data.a = 1`、`delete data.a`、数组增删都是常规操作，不是高级功能；只读实现会立刻在真实用法上露馅——调用方拿到数据后改不了，只能整棵树重建或另建一套可变结构。

## 与 0001 的关系

树模型是这条决策的**前提**：视图是源文本上的字节区间，无法原地增删键值，也谈不上写入。所以两条决策互相支撑，不是并列的两件事：

- 0001 决定「用什么承载数据」（树）；
- 0002 决定「公开范围到哪里」（读 + 写）。

反过来，如果只保留 0001 而不做写入，树就只剩读路径，无法兑现「对齐 JavaScript 用法」的目标。

## 操作面（只列范围，不定 API 形态）

函数名、签名、错误码与所有权表达方式均不在本 ADR 决定。

### 读

| 能力 | 要解决的问题 |
| --- | --- |
| 按 key 取值 | 对象成员访问，对应 `data.a` / `data["a"]`；键须按反转义后的语义比较 |
| 按下标取值 | 数组元素访问，对应 `arr[i]` |
| 类型查询 | 判断节点是对象、数组、字符串、数字、布尔还是 null，供调用方分支 |
| 判空 | 区分 JSON `null`、键不存在、空容器三种状态；C 侧最容易把三者混成一个空值 |
| 对象键遍历 | 按插入序枚举对象成员，供序列化与业务遍历 |
| 数组遍历 | 按下标顺序枚举元素 |
| 编码回字符串 | 把树写成 JSON 文本；数字、转义与键序需与 0001 的口径一致 |

### 写

| 能力 | 要解决的问题 |
| --- | --- |
| 设置对象成员（不存在则新增、存在则覆盖） | 对应 `data.a = 1`；覆盖时要处理旧值的释放与顺序保持 |
| 删除对象成员 | 对应 `delete data.a`；删除后键序与已持有引用的有效性需要规则 |
| 数组追加 | 对应 `arr.push(x)`；扩容不得让已取得的元素引用失效（0001 设计口径 1） |
| 数组按下标覆盖 | 对应 `arr[i] = x`；旧值释放与元素身份保持 |
| 数组插入 | 对应 `arr.splice(i, 0, x)`；插入点之后的元素会移位，引用语义需要规则 |
| 数组删除 | 对应 `arr.splice(i, 1)`；删除点之后的元素会移位，引用语义需要规则 |
| 整棵树释放 | 对应 0001 的显式 `json_free`；写入路径产生的临时值也必须有归宿 |

## 待定（留给用户裁定，本 ADR 不选）

### 1. 写入时拷贝值还是接管所有权

> **已由 [ADR-0003](0003-reference-sharing.md) 回答（2026-11-15）：** 既不拷贝也不转移，写入同一对象的引用，生命周期由引用计数管理。以下原文保留备查。

- 分歧：调用方把一个已有子对象挂到树上时，库是复制一份，还是接管这个指针。
- 选「拷贝」：调用方可以继续复用同一个子对象，栈上临时值也能直接写入；代价是深拷贝开销与额外分配，且同一子对象挂两处会变成两份，与 JavaScript 的引用共享语义不同。
- 选「接管」：零拷贝、更接近 JavaScript 的共享引用；代价是调用方不能再复用或自行释放，栈上值不能直接写入，双重释放需要额外规则兜底。

### 2. 删除键或元素之后，外部已持有的引用怎么处理

> **已由 [ADR-0003](0003-reference-sharing.md) 回答（2026-11-15）：** 由引用计数判定存活——还有引用就活着，计数归零即释放，不需要版本号。以下原文保留备查。

- 分歧：删除会让被删节点失效，数组删除与插入还会让后续元素移位；外部指针是否要能被检测出来。
- 选「失效判定」（版本号 / 代际）：访问时能报错而不是读悬垂内存；代价是每节点或每容器增加开销，所有访问路径都要检查，API 也要暴露失败可能。
- 选「不做保护」：实现最简单、零额外开销；代价是文档只能约定「删除后旧引用一律失效」，误用即未定义行为。

### 3. 写入数字时的精度策略

- 分歧：0001 已定「数字保留原始字面量」；写入路径是继续保留字面量，还是把输入归一成 `double`。
- 选「保留原始字面量」：与 0001 一致，`1.0` 不塌成 `1`、大整数不丢精度；代价是写入入口必须能接受词法形式（字符串或等价表示），直接传 `double` 时还要决定如何生成原文。
- 选「按 `double` 归一」：写入 API 最简单，一个数值类型就够；代价是超过 2^53 的整数丢精度、`1.0` 与 `1` 不可区分，与 0001 的口径直接冲突。

### 4. 类型不匹配的写入（往数字位置写字符串）

- 分歧：目标位置已有节点、新值类型不同时，是拒绝还是替换。
- 选「报错」：树保持不变，调用方必须显式先删再写；代价是多一步操作，且批量修改时要处理部分失败。
- 选「覆盖」：更接近 JavaScript（`data.a = "x"` 本来就允许改类型）；代价是要释放旧子树，旧引用随之失效，并与第 2 条的保护策略耦合。

## 不做什么

- 不定义函数名、签名、错误码与所有权表达方式。
- 不写实现、不恢复开发、不新建夹具、不修改 `json.ct`。
- 不替用户裁定上面四条待定项。
