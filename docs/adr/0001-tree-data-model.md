# ADR-0001：树作为唯一公开数据模型

- 状态：已采纳（Accepted）
- 日期：2026-11-15
- 裁定者：用户
- 废止对象：`DECISIONS.md` §1 的「零分配视图唯一」；§6「不提供可变 API」的正式废止见 [ADR-0002](0002-mutable-scope.md)
- 后续修订：写入共享与 `json_free` 减计数语义见 [ADR-0003](0003-reference-sharing.md)
- 依据：ct-json 0.1.0 两份评审（[主张席](../review/ct-json-0.1.0-advocate.md)、[反证席](../review/ct-json-0.1.0-rebuttal.md)）与[合论](../review/ct-json-0.1.0-verdict.md)
- 影响面：公开数据模型。本 ADR 不含实现，不改变当前 `json.ct`。

## 背景

0.1.0 的既有实现是零分配只读视图：文档只保存源文本指针、长度与首个错误偏移，`JsonView` 是 `{start, len}` 的字节区间，每次访问按需重扫。该形态满足「校验 + 少量查找」，但满足不了 JavaScript 风格的访问方式。

## 决策

1. **树是唯一公开数据模型。** 这里的「树」指构造方式与公开模型，不限制共享：自 ADR-0003 起允许多个父持有同一个子对象，形式上是 DAG。
2. **零分配视图降级为后续可选的只读层**，不影响公开 API；它不是并存的第二套公开模型。
3. 本决策是对既有决策条款的**废止**，不是叠加重申：`DECISIONS.md` §1 与 §6 不再作为设计依据，原文保留备查。

## 理由

### 1. 对象身份与可变性

`data.server` 与 `data["server"]` 必须指向同一个对象，对象要能增删键。视图每次查找返回两个独立的字节区间，没有对象身份，也不能原地增删；任何修改都只能整段重建。

### 2. 键必须反转义

`{"a\u0062":1}` 的键语义上是 `ab`。视图保留原始字节，调用方每次按键查找都要自己反转义并处理代理对与控制字符；树在解码时一次性归一化键，之后按归一后的键比较与枚举。

### 3. 编码成本只是推迟

视图在读取时省下分配，但 encode 仍要把值重新物化；省下的分配会在写回时还回去，而且往返（数字字面量、转义形式）更难保证原样。

## 设计口径

1. **指针稳定**：节点独立分配；容器扩容不得让已取得的引用失效。
2. **对象保插入序**：有序指针数组 + 哈希索引，查找 O(1)，encode 按插入序输出。
3. **数字保留原始字面量**：`1.0` 不塌成 `1`，大整数不丢精度，encode 可原样吐回。
4. **显式释放**：用 `json_free`，不依赖 `Drop`（跨单元 `Drop` 当前是空桩）。自 ADR-0003 起，`json_free` 的语义是**减计数**，计数归零才真正释放，不是无条件销毁。

## 已知代价

解码内存峰值高于视图：每个节点、键、字符串都要独立分配。后续可用 arena（一次大块分配 + 指针碰撞）摊销；该优化不改变本节接口与语义。

## 不做什么

- 不定义具体结构体、函数签名与错误码；这些属于实现设计，另行确定。
- 不恢复被暂停的开发，不新建夹具，不修改 `json.ct`。
- 不承诺 arena 或视图只读层的时间点。
- 不补未做的功能列表。

## 后续约束

- 实现设计须重新核对评审列出的阻断项（匿名 union、裸泛型、跨单元导出、`own`、Drop 空桩、`#define` 导出）。
- `docs/requirements.md` 的 Q-01 以本 ADR 的裁定为准；该文件不在本次修改范围内。
